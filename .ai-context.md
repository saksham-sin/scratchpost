# ScratchPost Workspace Context

ScratchPost coordinates multiple coding agents operating in one master workspace.
The canonical master workspace is daemon-owned. Agents run only inside physical
session workspaces under `.scratchpost/sessions/<agent>/workspace/`.

- Binary: `sp` (also acts as `scratchpostd`, the `git` shim, the hook runner,
  and the stdio MCP server).
- State root: `.scratchpost/`.
- Primary invariant: never mutate the master working tree from an agent session.
- Git commits are gated by short-lived commit permits, immutable staged-index
  snapshots, and managed pre-commit/pre-push hooks.
- Sequence claims are deterministic and stored in the daemon ledger.
- Barriers are scoped per conflict component by default (`barrier_scope=component`),
  so orthogonal agents never wait on each other.
- The daemon runs a fixed 16-thread RPC pool; never spawn a thread per connection.

## Module map

| Module | Responsibility |
|---|---|
| `protocol` | Versioned ledger, RPC, permit, conflict, and notice types |
| `workspace` | Master discovery, state layout, socket endpoint, hooks, CoW copies |
| `ledger` | Double-buffered seqlock mmap snapshot and append-only WAL |
| `git_engine` | Sanitized real-Git subprocesses and worktree operations |
| `rules` | Liquibase/Flyway sequence extraction and allocation |
| `prompt` | Deterministic passive conflict-resolution output |
| `session` | Worktree, context, cache, and resource-band provisioning |
| `daemon` | Single-writer authority, commit gate, claims, barriers, WAL replay |
| `shim` | `git` interception, index snapshot, hooks, permit execution |
| `client` | Unix-domain socket RPC and notice cursor |
| `agents` | Agent-first documentation and harness scaffold generator |
| `style` | Terminal presentation: colour gating, headers, aligned key/value blocks |
| `mcp` | MCP JSON-RPC stdio transport and tools |
| `ui` | Embedded HTTP/SSE Mission Control server |
| `cli` | Command surface and session child environment |

## Commands

```sh
sp init
sp daemon
sp shell --agent <name>
sp run --agent <name> -- <command>
sp status [--json]
sp claims / sp notices
sp claim --agent <name> --repo <repo> --path <relative> [--strength advisory|mandatory] [--ttl-ms <n>] [--note <text>]
sp claim --agent <name> --release
sp instructions [--print]
sp config --mode <fcfs|barrier-stacked|barrier-integration>
sp config --barrier-scope <workspace|component> --barrier-timeout-ms <n>
sp barrier status|arrive --agent <name>|release [--scope <workspace|component>] [--component <key>]
sp sequence next --namespace <name> --after <n>
sp resequence --agent <name> --file <relative> --from <key> --to <key>
sp sync --rebase --agent <name> [--repo <name>]
sp evict --agent <name>
sp ui
sp --mcp
```
